# E22 — Panel web completo

## Entrada y lectura mínima

Prerrequisito: E21 implementada; consultar ESTADO para pruebas pendientes. Si existe un bloqueo externo, avanzar solo en subtareas independientes y conservar el gate pendiente.

Consultar documentos 01 D03–D07; 05 U08; 03 auth. Los números 01–07 corresponden a los archivos raíz del paquete. Las decisiones de arquitectura no se reabren sin una incompatibilidad demostrada.

## Superficie de cambio

web routes/components; shared generated API types. Los nombres de módulos nuevos son destinos de trabajo; los símbolos Swift existentes se ubican mediante búsqueda, sin inventar archivos presentes. Cada cambio de esquema exige migración y cada endpoint exige contrato.

## Subtareas, en orden

1. **E22.01** — Implementar shell y login con cookies seguras/CSRF; rutas por permiso y sucursal, filtros en URL y navegación teclado. No duplicar reglas de negocio en frontend.

2. **E22.02** — Construir dashboard general y todos los maestros–detalle: sucursales, infraestructura, precios, proveedores/compras, inventarios, usuarios/personal, cortes, incidencias, tienda, gastos y mantenimiento.

3. **E22.03** — Reutilizar operaciones API existentes para altas, edición, aprobación, exportación y configuración; mostrar acciones no disponibles con motivo de estado cuando sea útil.

4. **E22.04** — Usar tablas paginadas con filtros persistentes, panel de detalle, acciones masivas autorizadas y revisión de resultados parciales. Evitar exigir decenas de swipes en escritorio.

5. **E22.05** — Probar flujos completos con Playwright y restricciones de operador/local/general. Verificar responsive, accesibilidad y paridad de datos con iOS.

## Criterios de aceptación

Web es un cliente operativo real del mismo sistema y no una maqueta con datos diferentes. Mutación en web se refleja en consultas iOS y viceversa.

## Verificación dirigida

T10,T35,T39; recorrido G2 completo; CSRF, sesión expirada y edición concurrente entre clientes.

Añadir casos negativos de permiso, estado inválido y repetición para las nuevas operaciones mutantes. Ejecutar las pruebas afectadas, contratos y compilación del componente cambiado; ampliar solo ante riesgo concreto.

## Cierre y continuidad

Registrar en `ESTADO.json` subtareas realizadas, archivos/commit, migraciones, pruebas ejecutadas con resultado, evidencia y siguiente acción exacta. Código escrito no equivale a prueba aprobada. Un impedimento de Mac/proveedor deja la verificación correspondiente pendiente. Preservar las decisiones y los defectos restantes; no pedir al usuario autorización repetida para continuar el alcance ya aprobado.
